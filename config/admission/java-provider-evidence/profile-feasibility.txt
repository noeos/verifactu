Official-vector check
---------------------
The official PDF version 0.1.5 explicitly fixes the signature-policy digest to
SHA-1 and confines that use to policy verification; it separately directs that
the invoice/event record signature use SHA-256. The signed official vector uses
RSA-SHA256 and SHA-256 document/reference digests while its signature-policy
digest and certificate-reference digests use SHA-1. The profile must preserve
that exact contextual distinction, never broadly enable SHA-1 for record
signatures or document/reference digests.

The local loopback network attempt was denied before connection; configured
AIA/CRL/OCSP sources were null. The vector is not evidence of trust, policy
acceptance, AEAT acceptance, or legal approval. DSS emits default-policy SHA-1
certificate-reference warnings for the official legacy vector; P4-D must
narrowly implement the source-bound algorithm contexts above and verify them
independently.

Scope boundary
--------------
These are synthetic feasibility observations on Linux x64 and do not prove a
real HSM, multi-platform provider compatibility, P4-D behavior, legal review,
AEAT acceptance, fiscal compliance, publication, or release readiness.
P4-D must independently implement and test profile topology, certificate
trust/time/usage/algorithm policy, opaque-key isolation, bounded cancellation,
network denial, and fail-closed CRL/OCSP processing against exact artifacts.
