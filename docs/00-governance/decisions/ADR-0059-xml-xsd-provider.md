# ADR-0059: XML and XSD provider admission

## Context and spike

P4-C needs standards-based validation of the immutable AEAT schema closure,
safe XML parsing, offline resolution and resource supervision. A time-bounded
spike used the exact `rrsif-2026-09-21-authoritative-candidate` schema bytes and
the official signed AEAT example (`SRC-0024-EXAMPLES`). The source schema
digests remain those in the immutable source snapshot; the W3C XMLDSig schema's
DOCTYPE is removed only from a digest-checked in-memory copy because it has an
internal DTD subset. Input XML with a DOCTYPE or entity declarations is
rejected after parsing. No source snapshot is rewritten.

The official positive XML vector passed both lxml/libxml2 and xmlschema. Three
minimal schema mutations (invalid invoice type, invalid fingerprint type, and
missing required `IDVersion`) were rejected by both. Hostile DTD/entity inputs
did not resolve their external resources in the configured lxml parser, and an
unknown imported schema URI was rejected by the exact resolver. With schemas
precompiled, the 11.3 KB official vector took about 4.5 ms for 100 validations
in lxml and 518 ms in xmlschema in this single local run. This is selection
evidence, not a performance guarantee or a replacement for the frozen matrix.

## Options considered

- `lxml==6.1.3` with libxml2 2.14.6: selected as the primary candidate. It
  compiled and validated the complete schema closure, has Python 3.13 wheels
  for the frozen Ubuntu x64, Windows x64 and macOS universal2 cells, and
  supports a custom resolver and real XSD validation. Its native parser must be
  isolated behind the private worker boundary and explicitly configured.
- `xmlschema==4.3.2` with `elementpath==5.1.4`: selected as the independently
  implemented test oracle, not the runtime primary. It supports the closure and
  exposes explicit sandbox/no-resource and defusing controls. Its much slower
  observed vector time makes it a less suitable per-request primary; the
  independent implementation is useful for differential conformance.
- `libxml2-wasm`: rejected for this wave. Its upstream documentation describes
  XSD include/import support as experimental; it uses the same libxml2 engine,
  so it would not provide an independent validation oracle, and it adds WASM
  memory/disposal supervision.
- A Java XML provider: deferred. It would introduce a second provider runtime
  before there is evidence that lxml cannot meet the frozen contract.

## Decision and exact admission

Admit lxml 6.1.3 / libxml2 2.14.6 as the P4-C primary-provider candidate, with
xmlschema 4.3.2 / elementpath 5.1.4 as the independent oracle. Exact Python
package versions and all PyPI file hashes are recorded in
`config/admission/python-dependencies.json` and the hash-locked
`config/python/requirements.lock`; the lock is generated by admitted uv
0.12.5. The selected release artifacts were published 2026-09-02 and exceed
the seven-day cooling period. `config/admission/external-tools.json` records
the uv 0.12.5 Linux x64 release archive and digest; the release checksum file
was independently checked against the downloaded archive.

Configure lxml with `load_dtd=False`, `resolve_entities=False`,
`no_network=True`, `huge_tree=False`, and a resolver that raises on every URI
outside the closed digest-pinned schema map. Reject any parsed document with a
DOCTYPE or entity declaration, and reject XInclude. Never treat parser success
as XSD or semantic success. Use bounded streaming input, a private asynchronous
worker with a hard deadline, cancellation, output ceilings and process
termination. Schema inputs may be materialized only from the immutable
snapshot; the W3C DTD removal is a deterministic derived in-memory artifact
bound to the exact original digest. Redact parser text that might echo taxpayer
input.

The Python packages are private build/provider dependencies and must not enter
the public npm package archive. The lxml wheel is BSD-3-Clause and bundles
native zlib, iconv, libxml2, libxslt and libexslt components; preserve and
inventory every bundled notice, including iconv's LGPL-2.1 terms, in the
provider's complete SBOM/NOTICE closure. xmlschema and elementpath are MIT.
The exact platform wheel hashes are included in the lock. Package admission
and local spike evidence do not replace vulnerability review, clean
reproducibility, platform execution, resource-attack tests, or a competent
licence review before distribution.

## Consequences and qualification gates

This selection admits package inputs only; P4-C implementation may start after
this decision and dependency/tool admission are protected on main. The worker
must prove safe behavior under the frozen compatibility cells and adversarial
population, including no DNS/HTTP/file access, no DTD/entity/XInclude
processing, closed imports, bounded expansion and diagnostics, cancellation,
crash handling, deterministic serialization and independent round trips. Any
failure blocks P4-C and requires a successor decision; it does not authorize a
weaker parser or an XSD/semantic/AEAT-validity claim.

`creationAllowed` remains false. No compliance, AEAT acceptance, publication or
release claim follows from this ADR or from XSD validation.
