# Preparación de release 1

Estado: **normativo**

La release 1 no comienza por fecha, sino al completar todos los gates. Se congelarán fuente/edición, API, contratos, toolchain y escenarios; cualquier cambio posterior reinicia las validaciones afectadas.

El candidato se prueba como tarball, no desde workspace. Se conserva matriz de compatibilidad con Verification Engine, adapters y Node. Los artifacts se firman y verifican antes y después de npm.

La comunicación pública describe capacidades exactas, modalidades, ediciones, limitaciones, soporte y ausencia de respaldo AEAT. No se publica un badge de conformidad sin definir qué evidencia representa.

La decisión final documenta riesgos residuales y comprobaciones no realizables. Ninguna comprobación ausente se rellena con una declaración manual de éxito.
